| | |
|---|---|
| **The arithmetic (live, 08-03)** | Q1 actual $1,282.5M + Q2 actual $1,329.0M + BBG Q3E $1,241.2M + BBG Q4E $1,225.4M = **$5,078.1M**, and EPS $2.56 + $2.47 + $1.988 + $1.942 = **$8.96**. But the **`estimates.json` CY2026 line reads $4,898.8M / $8.08**. |

| **Root cause — the 08-01 hypothesis was wrong** | This report attributed the gap to *"a staler contributor set at the annual level than at the quarterly level"* and prescribed a re-run. **A re-run cannot fix it, because the defect is in our own calendarization.** `fetch_estimates.py` builds each CY as a sum of quarters and, for quarters already reported, deliberately re-pulls them via `BEST_FPERIOD_OVERRIDE` (`0FQ`, `-1FQ`, …) to keep the whole sum on one non-GAAP basis. **But `BEST_*` on a past fiscal period returns the last pre-print consensus mean, not the comparable actual.** |
| **Probe (live, 08-03)** | TER Q1 CY26: actual **$1,282.5M / $2.56** vs `-1FQ` **$1,215.0M / $2.107**. Q2 CY26: actual **$1,329.0M / $2.47** vs `0FQ` **$1,217.2M / $2.044**. Shortfall **$67.5M + $111.8M = $179.3M** and **$0.453 + $0.426 = $0.879** — **matching the CY gap exactly.** Same probe on KLAC: Q1 $3,415.1M vs $3,370.8M, Q2 $3,657.6M vs $3,600.1M = **-$101.7M**, matching its -$102M CY gap. |
| **Scope — this is systematic, not a TER quirk** | **Every CY2026 line understates a company that beat and overstates one that missed, by the size of the beat/miss in the already-reported quarters.** It scales with beat size, which is why TER (a large beater: +5.6% and +9.2% on revenue) shows -9.8% on EPS while KLAC (roughly in line) shows only -1.6%. **every one of the 97 names carries ≥1 reported 2026 quarter (53 names with 1, 44 with 2), so the CY2026 line is affected for all of them. CY2027 is clean — `n_actual = 0` for all 97** — so out-year comparisons, which is where most of the edge tracker lives, are unaffected. |
| **Why it matters operationally** | ⚠️ **The wiki's derived artefacts read these CY lines.** The `📊 Consensus snapshot` block on TER.md and the edge tracker both consume `estimates.json` CY2026/CY2027 — so **any CY2026 house-vs-consensus or guide-vs-consensus comparison for TER is being run against a number ~10% light on EPS.** Compounds with ①: the TER "house vs consensus" edge is wrong in *both* directions at once (house stale-low, consensus CY26 artificially low). |
| **Verdict** | 🔴 **Superseded action.** The prescribed fix (re-run the fetch) is now known not to work and should not be repeated. **Correct handling until the calendarization is fixed: for any CY2026 comparison use the sum-of-quarters ($5,078.1M / $8.96 for TER), not the CY2026 line; treat CY2027 as reliable.** The underlying fix — using the reported adjusted actual for already-printed quarters instead of the past-period `BEST_*` mean — is a change to the shared consensus baseline for all 97 names and was **deliberately not made in this unattended run** (see method flag 7). |

   - **Not fixed in this run, deliberately.** Correcting it changes the consensus baseline for all 97 names simultaneously, which is exactly the kind of silent baseline shift that reconciliations are supposed to guard against; it needs a human decision, not an unattended edit. **Interim rule: for CY2026 comparisons, use the sum of the quarterly lines rather than the CY2026 aggregate.**
